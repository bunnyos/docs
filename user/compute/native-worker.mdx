---
title: "Run a worker"
description: "Register a worker in the Mini App, start it on your own machine with one command, and earn Carrots for every job it serves."
---

A worker is a small program you run on your own computer. It downloads a model, connects to bunnyCompute, and answers requests for the network. You earn Carrots for every job it serves, and [Contribute compute](/user/compute/overview) covers what each job pays.

<Note>
This is the most technical page in the docs, because it asks you to type one command into a terminal. Everything else happens in the [Mini App](/user/getting-started/mini-app). If terminals are not your thing, [staking `$OS`](/user/carrots/stake-os) earns Carrots without one.
</Note>

## What you need

- A computer with a real GPU or Apple Silicon. A laptop on integrated graphics will not keep up.
- Node.js 18.17 or newer.
- Ollama, from [ollama.com](https://ollama.com). The worker uses it to run the model.
- About 6 GB of free disk space for the model.

## Set it up

<Steps>
  <Step title="Register a worker">
    In the Mini App, open **Supply Compute** under **Earn Carrots**. Add a **Worker label (optional)** if you want to tell your machines apart later, then tap **Register worker**.
  </Step>
  <Step title="Copy your key">
    The **Worker registered** dialog shows the key once, and it cannot be retrieved afterwards. Copy it before you tap **Done**. If you lose it, just register another worker.
  </Step>
  <Step title="Install Ollama">
    Download and install it from [ollama.com](https://ollama.com) on the machine you want to use.
  </Step>
  <Step title="Start the worker">
    Open a terminal on that machine and run the command below, pasting your key in place of `<your key>`.

    ```bash
    npx @bunnyosai/worker@latest --key <your key>
    ```

    The first run downloads the model, warms it up, and measures how fast your machine is before it connects. Machines that are too slow are turned away, so if that happens, close anything graphics-heavy and try again or move to a faster GPU.
  </Step>
  <Step title="Leave it running">
    Once it connects it serves jobs until you stop it. Press `Ctrl-C` in the terminal to stop.
  </Step>
</Steps>

<Tip>
Add `--save-creds` to store the key on that machine, so you do not have to paste it in every time you start the worker.
</Tip>

## Check on it

Your machines are listed under **My workers** on the **Supply Compute** screen, each with a status dot and how long ago it was last seen.

| Status | What it means |
| --- | --- |
| Offline | Not connected right now. |
| Connecting | Starting up and joining the network. |
| Idle | Connected and waiting for a job. |
| Working | Serving a request this second. |

**Revoke** disconnects that worker immediately and stops its key from working. It is permanent, so register a fresh worker if you want the machine back on the network.
